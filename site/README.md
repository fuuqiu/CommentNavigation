# Code Comment Navigator — marketing site

Static [Astro](https://astro.build) site (SSG, zero client JavaScript) for the
Code Comment Navigator IntelliJ IDEA plugin, deployed to **Cloudflare Workers Static
Assets** at <https://commentnavigation.app.topxup.com>.

Two pages: English at `/`, Simplified Chinese at `/zh/`, plus `/404.html`.

## Commands

```bash
npm install
npm run dev                                                        # local dev server
SITE_URL=https://commentnavigation.app.topxup.com npm run build    # → dist/
npm run preview                                                    # serve dist/ locally
npx wrangler deploy --dry-run                                      # validate config + bundle
npx wrangler deploy                                                # publish (operator only)
npm run og                                                         # regenerate public/og.png + apple-touch-icon.png
```

`SITE_URL` is read in `astro.config.mjs` and decides the canonical URLs, the hreflang
alternates, the sitemap and the `Sitemap:` line in `robots.txt`. **Always build with it
set** (the fallback is the production domain, so a build without it is correct but a
build with the wrong value silently poisons every SEO signal). Changing the domain means
rebuilding, not just redeploying.

## Where the copy lives

| File | Holds |
| --- | --- |
| `src/i18n/index.ts` | URLs (`ROUTES`), section anchors, product facts (version, IDE, links, email), `MARKETPLACE_URL`, shared header/footer strings |
| `src/i18n/home.ts` | Every landing-page string for both languages, plus the IDE-mock and code-sample source text |
| `src/i18n/faq.ts` | The six FAQ entries per language (also feed the `FAQPage` JSON-LD) |
| `src/i18n/jsonld.ts` | `SoftwareApplication` + `FAQPage` structured data |
| `src/i18n/code.ts` | Build-time syntax colouring — the site ships no highlighter |
| `src/layouts/Base.astro` | The only place `<head>` is written: title, description, canonical, hreflang, OG/Twitter, JSON-LD |

Every product claim must be traceable to the plugin repository
(`README.md`, `src/main/resources/META-INF/plugin.xml`, `LICENSE.txt`). The FAQ answer
"it contains no network code" rests on a source check — grep `src/main/kotlin` for
`java.net`, `HttpClient`, `URL(`, `okhttp`, `ktor`, `Socket` before changing it.

## The `MARKETPLACE_URL` switch

`src/i18n/index.ts` exports a single constant:

```ts
export const MARKETPLACE_URL = '';
```

* **Empty (today)** — the JetBrains Marketplace listing for `cn.tinyue.commentnavigation`
  is not live and there are no GitHub Releases. The hero's primary CTA reads
  *"Get it on GitHub"* and links to the repository; the install section says the listing
  is being set up and walks through build-from-source → *Install Plugin from Disk…*.
* **Non-empty** — paste the real listing URL and rebuild. The hero CTA becomes
  *"Install from JetBrains Marketplace"* pointing at that URL, and the install section
  leads with the Marketplace step instead (the build-from-source steps stay as a
  fallback).

Never point it at plugin id `27390` or `cn.tinyue.console` — that is a different,
retired listing.

## Assets

`public/favicon.svg` is the plugin icon from `META-INF/pluginIcon.svg`.
`public/og.png` (1200×630) and `public/apple-touch-icon.png` (180×180) are generated by
`scripts/og.mjs` with `sharp`; both are committed, so a normal build does not need it.
Verify dimensions after regenerating:

```bash
sips -g pixelWidth -g pixelHeight public/og.png public/apple-touch-icon.png
```

## Deployment

Cloudflare config lives in `wrangler.jsonc`: worker `commentnavigation-site`,
`main: worker/index.ts` (a passthrough to `env.ASSETS`), assets from `./dist` with
`html_handling: force-trailing-slash` and `not_found_handling: 404-page`, and the custom
domain route. The repository root carries `.cf-deploy.json` for the `/cf` deploy skill.
